# v2.0.0 Test Plan

Date: 2026-08-19
Scope: the entry-into-service hardening round that shipped as the `v2.0.0` release
([tag](https://github.com/flysoftware-git/itinerary-generator/releases/tag/v2.0.0),
branch `v2`) — closing the v2 kickoff checklist's operational gaps, fixing a privacy
leak found while preparing the first public build, and documenting one known issue
deliberately left unfixed. Originally posted as a comment on
[PR #71](https://github.com/flysoftware-git/itinerary-generator/pull/71#issuecomment-5339330611);
this file is the same content kept in-repo so it doesn't require digging through PR
history to find.

## What changed

**AllTrails closure-marker false positive** (`97da323`)
Extended the existing attraction-side fix (raw fetched HTML being naively
substring-matched for closure phrases, catching stale HTML comments / non-visible
markup) to `_has_alltrails_closure_marker`, which used the identical fetch mechanism
and had the identical risk. No partial-closure exemption added on the AllTrails side —
no evidence an analogous pattern exists for trail pages, so it wasn't invented.

**V2 kickoff checklist — operational gaps** (`a4d54ea`, `87deab4`, `5476839`)
- Run ledger was hardcoded to `<output>/dev/run_ledger.jsonl` regardless of
  `--environment`, silently conflating dev/eval/prod history. Now resolves to the
  run's actual environment.
- `requirements.txt` pinned to the exact versions the reviewed build and full suite
  validated against (was all `>=`, no lockfile).
- Added CI (`.github/workflows/tests.yml`) — there was none before.
- Documented the release rollback plan (redeploy-from-tag, no runtime kill switch —
  this is a batch CLI, not a served process, so nothing is "live" between a bad run
  and a revert) and recorded the v2.0 entry-into-service baseline (cost, quality
  counters) from the actual reviewed run.
- Bumped `generator.__version__` 1.4.4 → 2.0.0.

**Privacy leak found and fixed** (`24f1b52`, `370fe1d`)
The first real `--environment prod` build — the one intended for the public
`Travel-apps` repo — rendered real personal data straight into `index.html`: Notion
trip-planning links (`planning_links`) in the header buttons, and specific lodging
property names. Neither had ever had a redaction path.

Added `--privacy-mode {auto,on,off}` (default `auto`): redacts `planning_links` and
`lodging.name` only when the resolved environment is `prod`, since that's the only
environment ever committed/published. Deliberately **not** redacted:
`lodging.location` and `lodging.checkin_time` — both are load-bearing (geocoding/
routing, restaurant-search anchoring, arrival-day schedule construction), so
redacting them would have degraded itinerary content, not just removed personal
data. A redacted planning link renders as an explanatory non-link placeholder rather
than vanishing silently. The same switch also suppresses the PWA "Install App"
affordance (button + native browser prompt) — an installable home-screen icon is a
stronger distribution signal than a redacted build should carry.

Caught two real bugs building this: an inverted `on`/`off` implementation
(`--privacy-mode off` didn't disable redaction) that unit tests didn't catch because
they were written against the same wrong logic — only a manual CLI smoke test
surfaced it; and a variable-shadowing bug in `html_assembler.py` where the
PWA-suppression code silently read the wrong `meta` dict and never fired, caught
immediately by its own test on first run.

**Footer** (`5b154cb`)
Generator footer now includes the manifest filename alongside the existing
generated-at timestamp.

**Docs** (`5de304c`, `5b154cb`, plus inline in the above)
`requirements.md` bumped to v2.2 with changelog entries covering all of the above;
`docs/reports/requirements-traceability-v0.30-to-v0.20.md` gets new rows for each
(marked `Tested` where real test evidence exists, `Inspect` where only manual
verification does — the ledger fix and CLI flag resolution have no automated
CLI-level test harness yet, flagged as a real gap rather than glossed over);
`design.md` gets the mechanism writeups plus doc-accuracy fixes found along the way
(stale testing-posture numbers/claims, a `bootstrap.ps1` reference that doesn't
exist).

**Known issue, documented not fixed** (`5b154cb`)
A live build showed a Moab→Telluride en-route Google Maps mismatch — same class as
the existing dipstick60/63/68 issues (a stop with no real geocoded coordinate
falling through to a free-text query that Google's own geocoder resolves to an
unrelated place, this time "San Juan Island National Historical Park" in Washington
state instead of "Rico Historic District"). Documented in `design.md`'s debt map
(#16) rather than fixed blind: evidence is screenshot-only (en-route stop selection
isn't stable run-to-run, so it couldn't be reproduced against fresh data), and this
exact function has a documented history of a "confident" fix (`optimize:true`)
making the same bug class *worse* until it was reverted. Deferred as a fast-follow.

## Test plan

- [x] Full suite green throughout: 1053 → 1219 tests, every commit in this range
  landed with `pytest tests/ -q` passing (final count 1219 passed, 0 failures).
- [x] New unit test coverage added alongside each fix (closure-marker HTML/
  script-noise stripping, privacy-mode resolution + redaction + placeholder
  rendering, PWA-install-suppression substitution, footer manifest-name rendering)
  — not just asserted, verified failing-then-passing during implementation (the
  inverted on/off bug and the `meta`-shadowing bug were both caught this way, not
  by inspection).
- [x] Manual CLI verification (no pytest, since `generator.main` has no `CliRunner`
  harness — noted as a gap in the traceability doc): `--environment prod`/`dev`/
  `eval` × `--privacy-mode auto`/`on`/`off`, all 4 meaningful combinations
  spot-checked via dry-run for ledger path/environment banner, and via a real run's
  `run_ledger.jsonl` for `privacy_mode`/`privacy_redacted`.
- [x] Verified against two real, paid generation runs (not synthetic fixtures) of
  the actual `C:/Dev/Sandbox/sw_manifest.yaml` production manifest: zero occurrences
  of any real Notion link or lodging brand name in the rendered `index.html`,
  `PWA_INSTALL_ENABLED = false` present, build fingerprint confirms the commit that
  generated it.
- [ ] Not verified: the Telluride en-route mismatch fix (none attempted, see above)
  and a from-scratch v1.4.6-baseline-vs-v2.0 quality/cost comparison run (recorded
  once, not re-verified this round) — both deliberately not chased with an
  additional paid run this session.
